# Core Values Discovery Session — Facilitation Guide

> **Status:** empty_template — filled in before and during the session
> **Team-required:** yes (see `rocksolid/rules/team-required-tools.md`)
> **Source:** Wickman, *Traction*, Chapters 3 and 4

## How to use this file

This is the facilitation guide for the 4-step clone exercise that
produces the company's Core Values for the V/TO™ (Vision/Traction
Organizer™) and the People Analyzer™. The method deliberately
*discovers* values rather than *inventing* them — the output is
anchored in real humans the team already works with, so the final
list describes lived culture rather than aspirational marketing copy.

The session runs approximately 2 hours. Work each step live; do not
skip ahead, do not rearrange.

## Non-negotiable rules

- **Leadership team only** — not delegated, not drafted by the
  founder alone
- **Off-site preferred**
- **Output is 3 to 7 Core Values** (fewer under-specifies, more
  dilutes)
- **Every value must pass the operationalization test below**
- **Don't finalize on the day** — let the list sit for about a
  month before locking it in

## The 4-step clone exercise

The order matters. Each step builds on the previous one; skipping
steps reliably produces worse output.

### Step 1 — Clone the people — 30 minutes

Each leader writes down, **privately**, the names of three people
they would clone if cloning were possible. The strong preference is
for people **already inside the company** — people the leader works
with regularly and whose behavior they have actually observed.
External examples (an iconic customer, a past employee, a public
figure) are a fallback only when the company is too small to produce
three internal examples. Privacy prevents the first speaker from
anchoring everyone else. Once every leader has their three names,
each walks up to the whiteboard and posts them. No critiques yet.

**Facilitator notes:**

- "Three names each, written down before anyone talks."
- If a leader struggles to name three, that is useful data — note
  it, move on.
- Do **not** let the team debate who is on the list. The list is the
  input, not the output.

### Step 2 — Extract the traits — 30 minutes

Work through the whiteboard name by name. For each person, the group
answers: "What is it about this person that put them on the list?
What do they actually do? How do they show up?" The facilitator
captures every trait named onto the board. The goal is **wide first,
narrow later** — duplicates, near-synonyms, and multi-word phrases
are all fine.

**Facilitator notes:**

- This is the only step that looks like a brainstorm. Encourage
  volume.
- Push past abstractions. If a leader says "she's honest," ask
  "honest how — what does she do that makes her honest?" Follow up
  until the trait is grounded in specific behavior.

### Step 3 — First narrow — 30 minutes

With the wide trait list on the board, start editing:

- **Cross out duplicates** — strike redundant entries
- **Combine near-synonyms** — merge items that point at the same
  underlying thing
- **Cross out "nice-to-have but not core"** — pleasant behaviors
  that aren't what makes the culture work
- **Circle items that keep coming up** — traits multiple leaders
  named independently are strong signals

Target at end of pass: **5 to 15 candidate values**. Push back
against the instinct to keep everything — a shorter list is sharper.
Final wording doesn't matter yet.

### Step 4 — Debate down to 3 to 7 — 30 minutes

The hardest step. For each candidate, run the four-question
operationalization test and either keep, drop, or merge:

1. **Would we hire for this?**
2. **Would we fire for this?**
3. **Would we review for this?**
4. **Would we reward or recognize for this?**

**If the answer is "no" to all four, it is not a Core Value.** It
may be a nice-to-have, an aspiration, or simply true — but it does
not belong on the list.

**Facilitator notes:**

- This is where the team fights. A value nobody will defend out
  loud is not core.
- Default for contested values: drop, not keep.
- Aim for the smaller end of 3 to 7.
- Check the "already true" test: can the team name a specific
  internal person who lives it? If not, it is an aspiration.

## The operationalization test

Before any candidate gets on the final list, it must pass this test:

> Could two reasonable members of the leadership team look at the
> same employee's behavior over the last quarter and reach the same
> conclusion about whether this value was lived or violated?

If yes, the value is operational. If no, it is too vague. The most
common failure is single-word abstractions — bare nouns like
"Integrity" or "Excellence" look like values but two reviewers
disagree on what behavior demonstrates them. The fix is to expand
each bare noun into a short phrase naming the specific behavior.

- [ ] Every value on the final list has been run through the test
- [ ] Every value that failed was rewritten or dropped

## Output

- [ ] A list of 3 to 7 Core Values, each operationalizable
- [ ] The list is captured in `vto.md` as the answer to Core Values
      (V/TO question 1)
- [ ] The same list is used as the column headers of the People
      Analyzer™ grid in `people-analyzer.md`
- [ ] The list will sit for approximately 30 days before being
      formally locked in, so second thoughts can surface
- [ ] Session notes archived with the raw trait list, the narrowed
      candidate list, and the final list for future audit

## Phase 1 vs Phase 2 note

This exercise can be run in **Phase 1** (People Component work — the
People Analyzer needs Core Values to grade against) or **Phase 2**
(the V/TO formally codifies Core Values as question 1). If a Phase 1
draft already exists, the Phase 2 session re-tests it against the
operationalization test rather than starting from scratch. A
clean-passing Phase 1 list becomes a formal ratification at Phase 2.
