# Phase 2 — Vision

**Phase number:** 2 of 3
**Tools covered:** 5 (V/TO™ — Vision/Traction Organizer™, all 8 questions)
**Goal:** With the leadership team already running on Rocks™ and Level
10 Meetings™, now make the vision explicit, shared, and team-owned —
and align the existing Phase 1 Rocks to the vision retroactively via
the Rock Alignment Check.

**Target weeks:** 14-22 (Standard tempo). Fast Track roughly weeks
7-11. Deep tempo roughly weeks 21-33. Week numbers are orientation
only — the hard logic is the substance check.

**Phase gate criterion:** Tool 5 (V/TO) passes its substance rubric in
`assessment/substance-rubrics.md`, all 8 sub-checks included, AND the
Rock Alignment Check has been completed for the current-quarter Rocks.

**Rationale (Wickman's Chapter 9, paraphrased):** Vision work only
becomes meaningful once the team already operates in a cadence of
Rocks and L10™. A team that is executing weekly has the context and
credibility to produce a vision that will actually be followed. A team
that isn't executing yet produces a wish list. Phase 1 built the
execution engine. Phase 2 points it in a direction.

## How to use this file

When the user is at Step 5 in this phase:

1. Read the step section below and its metadata block.
2. Load the knowledge blocks listed — the V/TO is structurally
   complex and the 8 sub-blocks describe how each answer is framed.
3. Copy `../templates/vto.md` into the deliverables folder if it
   doesn't yet exist.
4. Run the team-mode clarification protocol from
   `../rules/team-required-tools.md` — V/TO is explicitly team-only;
   a solo draft is a blocked phase gate until team-validated.
5. Work through the 8 questions with the user in the order below.
6. When a complete draft exists, run the substance rubric and report
   results. Each of the 13+ named checks must be addressed.
7. After V/TO passes: run the **Rock Alignment Check** described at
   the end of this file before closing the phase gate.

## Step 5 — V/TO™ (Vision/Traction Organizer™) — all 8 questions

**Metadata:**
- phase: 2 (vision)
- tool_number: 5
- target_weeks: 14-22 (Standard)
- team_mode: required (see `../rules/team-required-tools.md`)
- gate_level: non-negotiable
- prerequisite_steps: [1, 2, 3, 4] (all of Phase 1)
- knowledge_blocks:
  - `../knowledge/eos-vto.md`
  - `../knowledge/eos-core-values-discovery.md`
  - `../knowledge/eos-core-focus.md`
  - `../knowledge/eos-ten-year-target.md`
  - `../knowledge/eos-marketing-strategy.md`
  - `../knowledge/eos-three-year-picture.md`
  - `../knowledge/eos-six-components.md` (framing the V/TO against the full Six Key Components™)
- templates:
  - `../templates/vto.md`
  - `../templates/core-values-discovery-session.md`
- deliverables:
  - `{deliverables_path}/vto.md`
- substance_rubric: "See `../assessment/substance-rubrics.md` → Tool 5 — V/TO / Vision/Traction Organizer"

**Guidance:**

The V/TO is a two-page document that answers eight questions. Page 1
(Vision side) answers the first 5 questions, Page 2 (Traction side)
answers the last 3. The whole thing is the leadership team's
canonical statement of where the business is going and how it will
get there.

This is unambiguously a team-required tool. A V/TO drafted by a
founder alone on a Sunday is an artifact only the founder
understands; a V/TO produced in a two-day team off-site is an
artifact the team has agreed to execute. The skill will NOT mark this
deliverable substance-passed in solo mode — team validation must be
recorded, and draft-solo mode blocks the phase gate even if every
textual check passes.

Walk the user through the 8 questions in order. Treat each as its own
sub-step — some will already exist in informal form, others will
need the first real articulation the company has ever had. Use the
knowledge blocks for framing and the rubric for the bar.

### Question 1 — Core Values (3 to 7)

Load `../knowledge/eos-core-values-discovery.md`. Run the Core Values
Discovery session from `../templates/core-values-discovery-session.md`
— the "three people you'd clone" exercise. Derive 3-7 values, phrased
concretely enough to decide hire/fire/reward on. One-word
abstractions ("Integrity", "Excellence") fail the rubric — they need
to be rewritten so two reviewers looking at the same employee
behavior can agree whether it was lived or violated.

### Question 2 — Core Focus™ (Purpose/Cause/Passion + Niche)

Load `../knowledge/eos-core-focus.md`. The Core Focus has two halves:
the "why we exist beyond money" (Purpose/Cause/Passion) and the "one
thing we are already great at" (Niche). A Core Focus with only one
half is not a sweet spot — the rubric requires both, each phrased in
a few words.

### Question 3 — 10-Year Target™

Load `../knowledge/eos-ten-year-target.md`. A single Big Hairy
Audacious Goal with a concrete number and a dated horizon — not a
list of aspirations. "Become the leader in our space" fails the
rubric; "$50M revenue by Dec 31, 2034" passes it. Exactly one entry.

### Question 4 — Marketing Strategy

Load `../knowledge/eos-marketing-strategy.md`. Four required components:

- **Target Market** (The List) — specific enough that a real prospect
  list could be built from it. "Small businesses" fails; "US-based
  B2B SaaS companies with 20-100 employees and a dedicated revenue
  ops function" passes.
- **3 Uniques™** — exactly three, and no single competitor can
  honestly claim all three together.
- **Proven Process™** — named (e.g., "The Acme Difference"),
  visually illustrated, 3-7 major steps.
- **Guarantee** — concrete, OR a recorded and justified decision not
  to offer one. Roughly half of EOS companies skip it, which is fine
  if explicit.

### Question 5 — 3-Year Picture™

Load `../knowledge/eos-three-year-picture.md`. A future-date snapshot
with revenue target, profit target, measurables, and 10-20 "what it
looks like" bullets. Vague pictures produce vague plans — the bullets
need to be concrete enough that a team member reading them in three
years would recognize the state described.

### Question 6 — 1-Year Plan (Traction side)

3 to 7 SMART goals for the upcoming year, with a future date, revenue
and profit targets, measurables, and budget support. Teams that load
12+ goals systematically under-deliver — the rubric's upper bound is
enforced.

### Question 7 — Quarterly Rocks (Traction side)

The current quarter's Rocks appear here on the V/TO Traction page.
They must match the Rock Sheet (`rocks-q{current}.md`) produced in
Phase 1 Step 2 — if they've drifted, the cross-tool integration
check `rock_vto_alignment` will fail. This connects to the Rock
Alignment Check run at the end of this phase.

### Question 8 — Issues List (Traction side, long-term)

A separate long-term Issues List lives on the V/TO — things the team
has named but explicitly deferred from the short-term Issues List
that runs through L10. An empty long-term list is a recommendation
warning, not a non-negotiable block; it usually means the team isn't
surfacing strategic concerns rather than that there aren't any.

**Completion criteria (substance-pass condition):**

- All 8 questions are answered (no gaps)
- Core Values: 3-7, non-generic, operationalizable
- Core Focus: both Purpose/Cause/Passion AND Niche present
- 10-Year Target: single, dated, numeric
- Marketing Strategy: Target Market filterable, exactly 3 Uniques,
  Proven Process named and illustrated with 3-7 steps, Guarantee
  present OR explicitly and justifiably absent
- 3-Year Picture: future date + revenue + profit + measurables + at
  least 10 "looks like" bullets
- 1-Year Plan: 3-7 SMART goals with budget support
- Quarterly Rocks on V/TO match the current Rock Sheet
- Long-term Issues List exists (entries optional — empty produces a
  recommendation warning, not a block)
- V/TO is team-authored (team_validated: true in state)

**Reason if skipped:**

Phase 3 (Systemization) cannot usefully begin without a vision —
Core Processes lose their anchor, Everyone Has a Number has no
1-Year Plan to roll up to, and Quarterly and Annual sessions lose
their frame of reference. Skipping is a non-negotiable block.

**Unlock on completion:** The Quarterly State-of-the-Company Meeting
cadence activates after Vision-side draft is complete — see
`../cadences/quarterly-state-of-company.md`. This becomes the
recurring vision cascade to the full workforce (45-minute quarterly
meeting).

## Rock Alignment Check — post-V/TO phase activity

After Tool 5 substance-passes, but BEFORE the phase gate closes, the
skill runs a Rock Alignment Check against the current-quarter Rocks
that were set in Phase 1 without a V/TO in place.

### Why

Phase 1 Rocks were Pre-Vision Rocks — set on rough directional
instinct rather than against a documented 1-Year Plan. Now that the
1-Year Plan exists on the V/TO Traction page, each current Rock
needs to be checked: does it still serve the vision?

### Protocol

1. Load `{deliverables_path}/rocks-q{current}.md` and the 1-Year Plan
   section of `{deliverables_path}/vto.md`
2. For each current Rock, ask the user: "Does this Rock serve at
   least one 1-Year Plan goal? Which one?"
3. Record the mapping inline in the Rock entry:
   `aligned_to: [1yp_goal_id or 1yp_goal_short_name]`
4. For Rocks that do not serve any 1-Year Plan goal, present three
   options to the user:
   - **Keep** — the Rock serves the business in a way the 1-Year
     Plan doesn't yet capture; add the corresponding goal to the
     1-Year Plan instead
   - **Rewrite** — adjust the Rock so it serves an existing goal
   - **Drop at next quarterly session** — let the current quarter
     finish, but do not carry the Rock forward
5. Remove the "Pre-Vision Rocks" header note from `rocks-q{current}.md`
6. Update `eos-state.md`: `rock_alignment_check_completed: true`,
   with timestamp
7. Re-run the cross-tool integration check `rock_vto_alignment` from
   `../assessment/substance-rubrics.md`

The Rock Alignment Check is a one-time retroactive operation. From
next quarter onward, Rocks are set against the existing V/TO during
the normal Quarterly Planning cadence and alignment is automatic.

## Phase gate check

Phase 2 closes when all of the following are true:

1. Step 5 (V/TO) has `status: substance_passed`
2. V/TO `team_validated: true` is recorded in state (draft_solo is
   not sufficient — see `../rules/team-required-tools.md`)
3. Rock Alignment Check has been completed and logged in state
4. Cross-tool integration check `rock_vto_alignment` passes
5. Cross-tool integration check `scorecard_1yp_alignment` passes
   (Scorecard goals now tied to the 1-Year Plan)

**On gate close:**

- Update `eos-state.md`: `gates.phase_2.status: passed`
- Open Phase 3: `gates.phase_3.status: open`
- Set `current_phase: 3`, `current_step: 6`
- Announce Phase 2 completion to the user
- Celebrate — vision is now explicit, shared, and aligned with
  execution
- Offer to start Phase 3 Step 6 in the next session or right now

## Cadence unlocks during Phase 2

- After Vision-side draft complete (questions 1-5 answered and
  team-validated): Quarterly State-of-the-Company Meeting activates
  → `../cadences/quarterly-state-of-company.md`
- Traction-side draft does not unlock anything new — Rocks, L10, and
  Scorecard were already active from Phase 1

The Weekly L10 cadence and the 90-Day Rocks Cycle continue running
uninterrupted throughout Phase 2 — the team does not pause execution
while building the V/TO. Cadences run parallel to implementation.

## Bypass & skip handling

Step 5 is `gate_level: non-negotiable`. The two-round challenge
protocol from `../rules/non-negotiables.md` applies:

1. Round 1: the skill paraphrases Wickman's reasoning for why V/TO
   matters specifically at this point in the journey (traction
   first, then vision)
2. Round 2: the skill names the concrete downstream consequence — no
   1-Year Plan means Scorecard goals have nothing to tie to, Rocks
   have nothing to align to, and Phase 3 processes have no purpose
   to serve
3. Only after the second explicit confirmation does the skill mark
   the step `bypassed` and log it to `bypass_history` in
   `eos-state.md`

Because V/TO is also team-required, a draft-solo path creates a
**double block**: even if bypass were granted, the team-validation
flag would still be false and the phase gate would remain closed.
The only real way forward is to hold the team session.
