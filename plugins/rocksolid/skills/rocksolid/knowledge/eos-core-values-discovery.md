# Core Values Discovery

Core values are the small set of timeless, non-negotiable principles that
describe how a company actually operates and who thrives inside it. They
are the first answer on the V/TO™ (Vision/Traction Organizer™) and the
backbone of the People Analyzer™ used in the Entrepreneurial Operating
System™ (EOS™). The deepest mistake leadership teams make with core values
is also the most common one: they try to *invent* them by sitting in a
conference room and brainstorming abstract virtues. The result is always
the same — a list of generic single-word abstractions that nobody can
operationalize and nobody actually uses to make decisions. The book's
counter-method is to *discover* values rather than invent them, by running a
specific four-step exercise that anchors the final list in real humans the
team already works with.

## What core values are (and what they aren't)

Core values are descriptive, not aspirational. They name what the culture
already is when it is at its best, not what leadership wishes it were. The
test for whether something belongs on the list is not "does this sound
inspiring" but "can two reviewers look at the same employee's behavior and
agree on whether this value was lived or violated."

A useful core value has these properties:

- **Timeless** — it would still be a core value in five or ten years
- **Non-negotiable** — the company would refuse to compromise on it even
  if doing so would be profitable
- **Operational** — it can be used as a filter for hire/fire/review/reward
  decisions without ambiguity
- **Already true** — the company already has people living it, not just
  people talking about it

Anything that fails one of these tests is a marketing slogan, not a core
value.

## The 3-7 rule

The target range is between three and seven values. Fewer than three
under-specifies the culture — three values is barely enough surface area to
distinguish one company's character from another. More than seven dilutes
the list — beyond seven, no employee can remember all of them, no manager
can reliably apply them in a review, and the values stop functioning as a
shared filter.

Within the range, the smaller end is preferred. A team that lands on four
or five values has done sharper work than a team that lands on seven. The
rule is "less is more": fewer values, applied seriously, drive more
behavior than more values applied loosely.

## The 4-step clone exercise

The discovery process is a structured four-step exercise that the
leadership team runs together. It is not a brainstorm. The order matters,
and skipping steps reliably produces worse output.

### Step 1 — Each leader names three people they would clone

Privately, before the group discussion begins, each member of the
leadership team writes down the names of three people they would clone if
they could. The strong preference is for people already inside the
company — people the leadership team works with regularly and whose
behavior they have actually observed. External examples are a fallback
only when the company is too small to produce three internal examples.

The point of the privacy is to prevent the first person to speak from
anchoring everyone else. Each leader has to commit to their own three
names before hearing what anyone else picked.

### Step 2 — As a group, list the traits those people share

The team gathers around a whiteboard and starts naming the traits and
behaviors the people on the lists embody. This is the only step that looks
like a brainstorm: the goal is to get everything on the board, not to edit
or judge yet. Duplicates are fine, near-synonyms are fine, multi-word
phrases are fine. The team should expect to fill the whiteboard.

The reason this works is that the team is no longer reaching for abstract
virtues — they are looking at specific humans they already trust and asking
"what is it about these people that makes them so valuable to this
business." The output is grounded in observed behavior rather than
imagined ideals.

### Step 3 — First narrow to 5-15 candidate values

Now the editing begins. The team walks through the list and combines
duplicates, merges near-synonyms, crosses out the non-essential, and
elevates the items that keep coming up. The target at the end of this
pass is a working list of roughly five to fifteen candidate values.

The list is still too long to be a final answer, but it is sharper and
better organized than the raw whiteboard. Items that survive this step
are usually the ones that multiple leaders independently called out.

### Step 4 — Debate down to 3-7 truly core values

The hardest step. The team argues each candidate against the test
criteria — is this timeless, non-negotiable, operational, already true —
and either keeps it, drops it, or merges it into another. The argument
matters: a value that no leader is willing to defend out loud is not core.

The end state is between three and seven values that the entire
leadership team is willing to commit to publicly. If the team cannot
agree, the right answer is usually to drop the disputed value, not to
add it. A "core value" that requires negotiation to keep is not core.

## Why the clone exercise works

The exercise inverts the usual brainstorm pathology. A normal values
brainstorm asks "what should our values be," which immediately produces
a list of abstract virtues — integrity, excellence, teamwork, innovation —
that every company in the world could claim. The clone exercise asks
"who are the people we already trust, and what is it about them that we
trust." The answer is necessarily concrete because it is anchored in
observed behavior.

A second benefit: the clone exercise surfaces the values the company
*actually has* rather than the values leadership *wishes* it had. If
nobody on the leadership team can think of a single internal person who
embodies "innovation," then innovation is not a current core value — it
might be a future aspiration, but it cannot pass the "already true" test.

## The operationalization test

Before any candidate value gets onto the final list, it has to pass an
operationalization test:

> Could two reasonable members of the leadership team look at the same
> employee's behavior over the last quarter and reach the same conclusion
> about whether this value was lived or violated?

If the answer is yes, the value is operational. If the answer is no — if
two reviewers would draw different conclusions from the same evidence —
then the value is too vague to do any work. The most common failure is
single-word abstractions that mean different things to different people:
a single noun like "Integrity" looks like a value but cannot pass the
test, because two reviewers can disagree on what behavior demonstrates
integrity.

The fix is usually to expand the value into a phrase that names the
specific behavior. Instead of a bare noun, the team writes a short
sentence or phrase that describes what the value looks like in action.
The exact wording is up to the team, but the test is whether the phrase
gives two reviewers enough to agree on a verdict.

## Why values must be operationalizable

Core values that fail the operationalization test cause cascading damage
because they get used inside other tools that depend on them being
checkable:

- The People Analyzer grades each person against each value with a +,
  a -, or a +/-. Vague values produce inconsistent grades, which destroys
  the credibility of the entire tool.
- Hiring decisions that cite values as the rationale collapse if two
  interviewers cannot agree on what the values mean.
- Firing decisions that cite values as the rationale become legally and
  morally fragile if the values cannot be applied consistently.
- Review and reward conversations get dragged into definitional disputes
  instead of focused on actual behavior.

In short, vague values are worse than no values, because they create the
illusion of a filter without actually filtering anything.

## When the discovery process is run

The clone exercise can be run at two different points in the EOS journey:

- **Phase 1**, as part of the People Component work. The People Analyzer
  needs core values to grade people against, so a first draft of the
  values list often emerges during the early seat-and-fit work.
- **Phase 2**, as part of building the V/TO. The V/TO formally codifies
  the core values as the answer to question 1, and any earlier draft
  gets refined or finalized at this point.

The skill should treat the Phase 2 V/TO step as the formal commitment
moment, while accepting that a Phase 1 draft may already exist when the
team arrives at the V/TO session. If a Phase 1 draft exists, the V/TO
session is an opportunity to re-test it against the operationalization
criteria, not necessarily to start from scratch.

## Substance criteria

A core values list passes the substance check when:

- The list contains between three and seven values
- Each value is concrete enough to pass the operationalization test
- No value is a bare single-word abstraction (or, if it is one word, it
  is paired with a brief expansion that gives it specific meaning)
- The list was produced by the leadership team running the four-step
  clone exercise together, not by a single person drafting alone
- Every value can be tied to specific observed behavior in current
  employees — the "already true" test passes
- The list has been used at least once in a real hire/fire/review/reward
  conversation, demonstrating that it works as a filter

## Common pitfalls

- **Brainstorming abstract virtues.** Skipping straight to "what should
  our values be" produces generic single-word abstractions that fail the
  operationalization test. Use the clone exercise instead.
- **Single-word values with no expansion.** A bare noun like "Integrity"
  or "Excellence" cannot pass the two-reviewers-agree test. Expand into
  a behavioral phrase.
- **Aspirational values that no current employee embodies.** If nobody
  on the team can think of an internal example, the value is a wish, not
  a core value.
- **More than seven values.** The list stops functioning as a shared
  filter because nobody can remember it.
- **Founder-only authorship.** A values list drafted by the founder and
  approved by the team is not the same artifact as a values list the
  team built together. The commitment differs.
- **Marketing-copy values.** Wording that sounds good in a pitch deck
  but cannot be applied in a review conversation.
- **Re-litigating values every quarter.** Core values are timeless. If
  the team is rewriting them every cycle, that is a signal the original
  exercise was not done properly.
- **Values without operational use.** A list that exists on a poster but
  never appears in a hiring conversation, a review, or a People Analyzer
  grading is not a real values list.

## When to apply

- **Phase 1 People Component work**, as a first draft to feed the People
  Analyzer
- **Phase 2 V/TO session**, as the formal answer to question 1
- **Whenever the leadership team's hiring or firing decisions feel
  arbitrary** — usually a signal that the values list is too vague to
  filter with
- **Annual Planning Session**, as part of the V/TO walkthrough — but only
  to confirm the existing values still describe the culture, not to
  rewrite them
